# 발표 참고 요약 — 30초 매장 브리핑

> 발표자료(슬라이드)와 발표 스크립트를 만들 때 **사실 확인용**으로 쓰는 문서다.
> 여기 숫자는 전부 실측이며, 출처를 함께 적었다. 슬라이드에 옮길 때 그대로 써도 된다.
> 마지막 갱신: 2026-08-28 · 커밋 `ad61bde` 기준

---

## 1. 한 줄 정의

> 역 편의점 점포장에게 **매일 아침 3줄**을 배달하고, 관리자에게는 **여러 매장 보고서**를 만들어 주는 서비스.

부제로 쓸 만한 문장:

- "보고서를 읽는 시간을 30초로 줄인다."
- "숫자를 보여 주는 게 아니라, **오늘 무엇을 할지**를 말한다."

---

## 2. 문제 — 왜 필요한가

점포장은 숫자를 볼 시간이 없다. 기존 POS 화면은 **조회 도구**다 — 무엇을 볼지 알아야 볼 수 있다.

| 지금 | 이 서비스 |
|---|---|
| 점포장이 화면을 열고, 조건을 고르고, 표를 읽는다 | 아침에 3줄이 이미 와 있다 |
| "매출 2,999,800원" (그래서?) | "평소 화요일보다 33.4% 좋았어요" |
| 재고 화면과 매출 화면이 따로 | "○○ 재고가 얼마 남지 않았어요 — 오늘 채워 두는 게 좋아요" |

**핵심 주장**: 데이터가 없어서 못 한 게 아니다. **읽을 시간이 없어서** 못 했다.

     ▼

## 6. 발표에서 가장 강한 논점 3개

### ① "환각이 원천적으로 불가능합니다"

가장 자주 나오는 질문(**"AI가 지어낸 숫자 아닌가요?"**)에 대한 답이다.

- 문장은 **자유 생성이 아니라 분기와 치환**이다. LLM을 쓰지 않는다.
- 문장 계층에는 **산술 연산이 하나도 없다.** 반올림·절댓값·비교까지 전부 계산 계층에서 끝난다.
- 이것을 **정적 검사 테스트**가 지킨다 — 코드에 `+` 나 `sum()` 이 들어오면 테스트가 깨진다.
- `test_briefing_lines_use_only_json_numbers`: 3줄 안의 **모든 숫자**가 계산 JSON에 실제로 있는 값인지 검사한다.

> 스크립트: "문장이 숫자를 만들 방법이 없습니다. 코드가 만든 값을 끼워 넣을 뿐이고,
> 그걸 테스트가 강제합니다. 이 규칙을 어기면 빌드가 깨집니다."

**실제로 두 번 깨졌습니다** — 관리자 화면을 만들다 캡션에 `len()` 과 문자열 `+` 를 썼는데
정적 검사가 잡았습니다. 규칙이 살아 있다는 증거입니다.

### ② "침묵할 줄 압니다"

- 조건에 걸리지 않으면 "특별한 신호는 없어요"라고 말하고 끝낸다.
- 소형점은 396일 중 **30.8%가 침묵일**이다.
- 관리자 화면도 모든 매장이 평온하면 "먼저 볼 매장"을 **비운다**.

> 스크립트: "매일 뭔가를 말하는 시스템은 한 달이면 아무도 안 읽습니다.
> 말하지 않는 날이 있어야 말하는 날이 읽힙니다."

### ③ "매출과 재고를 함께 봅니다"

- 2줄은 우선순위로 갈린다: **재고 부족(G3) > 시간대 쏠림(G2) > 침묵(G6)**
- 매출이 잘 나온 날 재고가 부족해지는 인과가 그대로 문장에 담긴다.
- 관리자 화면에서는 **매출 3위 매장이 1순위로 지목**되는 날이 있다.

> 스크립트: "매출 순위표로는 나오지 않는 판단입니다."

## 7. 예상 질문과 답

**Q. 이 데이터 진짜인가요?**
A. 아닙니다. 화면 상단에 **🧪 목업 데이터** 배지가 상시 떠 있습니다.
실제 샘플은 점포 1곳·1일·거래 30건 이내이고, 그 역할은 데이터가 아니라 **씨앗**입니다 —
실컬럼 구조, 상품·가격 사전, 영수증당 1.4줄 패턴의 근거로만 썼습니다.
13개월치는 그 씨앗으로 생성한 가상 데이터입니다.

**Q. 재생성하면 숫자가 바뀌나요?**
A. 안 바뀝니다. 난수 시드가 `(기본시드, 점포, 날짜)` 에서 파생되어
**어느 구간만 다시 만들어도 같은 값**이 나옵니다. 화면에서 시연할 수 있습니다.

**Q. LLM을 쓰나요? API 키가 필요한가요?**
A. 안 씁니다. 외부 CDN·API·모델 다운로드가 **하나도 없습니다.**
폐쇄망에서도 그대로 돕니다. 정적 검사가 외부 호출 모듈 import 자체를 막습니다.

**Q. 개인정보는요?**
A. 카드번호·회원번호류 컬럼은 **스키마에도 없습니다.** 만들지 않았습니다.

**Q. 실제 1,300개 매장에서도 되나요?**
A. 1,300매장 × 40일을 실제로 만들어 확인했습니다. 화면 1회 로더 합계 **313ms**입니다.
매장 목록은 상위 20개만 담고 나머지는 분위수로 말합니다 —
1,300개에서 평균은 대형점 하나가 끌어올려 쓸모가 없기 때문입니다.
그래프 계열은 6개 이하로 묶습니다. 선 1,300개는 그림이 아닙니다.

**Q. 기간계(Oracle) 연동은요?**
A. `Extractor` 인터페이스로 분리해 뒀습니다. `OracleExtractor` 는 선언돼 있고
구현만 비어 있습니다(`NotImplementedError`). **연결 클래스 하나만 채우면** 나머지는 그대로 돕니다.

**Q. 발주 수량은 왜 안 알려주나요?**
A. 의도적으로 뺐습니다. "얼마 남지 않았어요 — 채워 두는 게 좋아요"까지만 말합니다.
수량 제시는 책임의 성격이 달라지고, 지금 데이터로 뒷받침할 수 없습니다.

**Q. 얼마나 걸렸나요?**
A. 명세를 원천으로 두고 TDD로 진행했습니다. 테스트가 소스의 0.70배 분량이고,
설계 판단 14건을 ADR로 남겼습니다.

## 8. 정직하게 말할 한계 (먼저 꺼내면 신뢰가 올라간다)

- **가상 데이터다.** 실제 매출이 아니며 배지로 상시 고지한다.
- **재고는 스냅샷이다.** 완전한 수불이 아니라 "어제보다 재고가 줄었다" 같은 문장은 못 만든다.
  씨앗의 수불 검산이 801건 중 544건(68%)만 맞았고 재고 음수 품목이 40개 있어,
  단순 공식으로 13개월을 만들면 화면에 "재고 −270개"가 뜬다. 그래서 스냅샷을 택했다.
- **매장별 상품 구성이 같다.** 세 매장의 분류 비중이 38.9/39.2/38.7%로 사실상 동일해,
  "상품 구성 차이" 자료는 만들 수 없다(넣으면 막대 세 개가 똑같이 나온다).
- **피드백 데이터가 없다.** `FEEDBACK_LOG` 0행이라 채택률은 아직 못 보여 준다.
- **화면이 2종으로 늘었다.** 명세의 "1페이지" 약속보다 제품이 커졌다.
- **전년 동월 비교는 7월만 된다.** 13개월치라 같은 달이 두 번 있는 건 7월뿐이다.

## 9. 배포 구성 (필요하면 한 장)

```
GitHub  hanjaejin/salesReport   코드·스키마·씨앗 사전만 (DB 파일 없음)
   │
   ├─ Streamlit Cloud           화면 (streamlit_app.py)
   │        │
   │        ▼
   └─ Supabase (PostgreSQL)     읽기 모델 134,373행
                                 원장은 보내지 않는다
```

- 연결 URL만 바꾸면 SQLite ↔ PostgreSQL이 오간다. **방언 종속 SQL을 처음부터 금지**한 덕이다.
- 원격 테이블은 RLS를 켜 두어 공개 키로는 읽히지 않는다.
