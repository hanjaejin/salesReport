**코레일유통 AI 챔피언 블랙 개인프로젝트 · 면담일: 2026-07-24 · 발표: 5분 + 라이브 데모**

| 항목 | 내용 |
|---|---|
| 프로젝트명 | 30초 매장 브리핑 — 매장 운영자 지원 서비스 |
| 발표자 | 한재진 (코레일유통 IT) |
| 오늘 면담의 목적 | ① 멘토님 의견이 프로젝트를 어떻게 바꿨는지 보고 ② 피벗 방향의 타당성 검증 ③ 남은 고민 6가지에 대한 조언 요청 |

## 1. 한 장 요약

> **"점포장은 바빠서 매출 분석을 볼 시간이 없다."** — 멘토님이 주신 이 한 문장이 프로젝트의 방향을 바꿨습니다. 분석을 '보게 만드는' 플랫폼을 버리고, **보지 않아도 되는 서비스**로 다시 설계했습니다: 매일 아침 결론만 3줄로 배달하고(30초), 점포장이 만들던 일일 보고서를 대신 만들어 둡니다. 요구하는 시간은 하루 30초, 돌려주는 시간은 보고 작성 시간 전부 — 이 **시간 수지가 흑자**인 것이 제품의 존재 증명입니다.

## 2. 프로젝트 목적 (두 겹)

1. **직영 매장 — 업무 생산성**: 점포장이 반복하던 조회·보고를 시스템이 대신하고, 점포장은 발주·진열·고객 응대(매출을 만드는 일)에 집중한다. 권역·본사의 계단식 취합(같은 숫자를 세 번 다시 만드는 구조)도 함께 소멸한다.
2. **개인 사업자 매장 — 공공기관의 사회적 가치**: 회사 POS에 데이터가 쌓이는데도 분석 여력이 없어 감으로 운영하는 소상공인에게, 확산 단계에서 데이터 기반 경영 지원과 이를 통한 매출 증대를 제공한다. 새 데이터 수집이 필요 없다 — 권한과 화면만 열면 된다.

## 3. 프로젝트 개요

### 3.1 제품이 하는 일 세 가지

| # | 기능 | 사용자가 하는 일 |
|---|---|---|
| 1 | **아침 30초 브리핑**: ①어제 결과 한 줄 ②오늘 준비 한 줄 ③특이 신호 한 줄 (신호 없으면 "평소대로 하시면 됩니다" — 침묵할 줄 아는 서비스) | 읽기 30초. 안 읽어도 불이익 없음 |
| 2 | **일일 보고 자동 대행**: 보고서가 이미 만들어져 있음 | 내려받아 제출 (1클릭) |
| 3 | **궁금하면 펼치기**: 매출·손님 수·1인당 구매액·TOP5·시간대 | 원하는 사람만, 원할 때만 |

### 3.2 작동 원리 (신뢰의 구조)

- 매일 새벽 자동 계산 (기간계 Oracle 무부하 원칙 — 분석 질의가 운영 DB에 가지 않음)
- **숫자는 코드가 계산, 문장은 검증된 값의 치환만** — 틀린 숫자가 화면에 나올 경로를 구조로 차단
- 개인정보는 처음부터 가져오지 않음 (원천 미적재)
- AI(LLM)는 표현 다양화 옵션일 뿐 — 없어도 서비스는 완결 동작

### 3.3 현재 상태와 데모 계획

- 산출물: 정식 설계서 v1.3(엔진 상세·감사 대응 수준) / 기획서 v1.1.1 / 피벗 설계서 v1.0(평가 6항목 구조) / **바이브코딩 구현 설계서 v1.1** (하루 구축 명세 — 비판적 자체 검토 7건 반영 완료)
- 데모: 합성 데이터(실컬럼·실패턴 기반, 점포 3곳 × 13개월)로 **생성→적재→집계→브리핑→화면→보고서 전 과정이 라이브로 흐름**. 화면에 "목업 데이터" 배지 상시 — 실데이터라고 말하지 않습니다
- Oracle 실연동은 목업 이후 단계이나, Extractor 교체만으로 붙도록 인터페이스를 고정해 둠

## 4. 멘토님 피드백이 만든 변화 (Before → After)

| | Before (매출 분석 플랫폼) | After (30초 매장 브리핑) |
|---|---|---|
| 사용자 행동 | 화면을 열러 간다 | 배달받는다 |
| 제품의 얼굴 | 분석 화면 4종 | 브리핑 3줄 (분석은 엔진룸으로 숨김) |
| 채택의 엔진 | 좋은 정보 | **"열면 보고가 끝나 있다" — 의무의 대체** |
| 시간 관점 | 사용자의 시간을 요구 | 사용자의 시간을 돌려줌 |
| 무열람의 의미 | 실패 | 실패 아님 — 보고 대행만으로 가치 성립 |

바뀌지 않은 것: 뒷단 엔진(데이터 정합·멱등 적재·개인정보 미적재·엔진/어댑터 재사용 구조)은 정식 설계서 v1.3 그대로 승계 — **피벗은 방향 전환이지 재출발이 아닙니다.**

## 5. 가져올 수 있는 변화와 이점

| 대상 | 변화 | 이점 (근거 표기 원칙: 측정 없는 수치 주장 안 함) |
|---|---|---|
| 점포장 | 조회·보고서 작성 소멸 → 아침 30초 | 보고 작성 [실측 예정]분/일 회수, "오늘 준비" 힌트로 품절·기회 손실 예방 (관찰 지표) |
| 권역·본사 | 취합·독촉·재가공 소멸 | 예외 점포 지원·전략 업무로 전환 — 감원이 아니라 업무 격상. **"점포장의 30초를 위해 만든 시스템이 수신자의 취합 몇 시간도 없앱니다"** (확산 지렛대 설득 문장) |
| 회사 | 연 2.97억 행 데이터가 매일 현장 행동으로 연결 | 데이터 자산의 현장 환류, 보고 채널·양식 파편화 정리 |
| 소상공인(확산) | 감 운영 → 데이터 기반 경영 지원 | 공공기관 사회적 가치의 실체 — 국민 편익 서사 |
| 타 기관(확산) | 같은 엔진 + 어댑터로 민원·예산 브리핑 | "바빠서 데이터를 못 보는 담당자"는 모든 기관에 있음 |

**시간 수지 (존재 증명식)**: 요구 30초/일 < 반환(보고 작성 + 조회 대기) [실측 예정] — 파일럿 1번 측정 항목. 수지가 흑자가 아니면 이 제품은 실패라고 설계서에 명시했습니다.

## 6. 확산 방법 — 3겹 동심원 ("밀지 않고 당기게 한다")

**역할 구분 먼저 (타겟은 바뀌지 않습니다)**

| 역할 | 누구 | 의미 |
|---|---|---|
| 고객(타겟) | **점포장 (불변)** | 고통의 당사자, 제품 설계의 기준 |
| 확산 지렛대 | 권역·본사 보고 수신자 | 채택 경로의 병목을 쥔 소수 — 수신자에게도 취합 소멸이라는 실익 제공 |
| 승인자 | 경영진·심사 | 도입 결정의 청중 |

### 6.1 사내 (코레일유통) — 지렛대: 수신자 선언

① 파일럿 실측 후기("나 보고 안 만든다") → ② **권역 수신자 선언**: 담당이 "이 양식으로 받겠습니다" 공지하는 순간, 점포장은 설득 없이 자동 유입(보고 의무를 벗는 유일한 길) → ③ **보고서 꼬리표**("30초 브리핑이 작성했습니다") — 보고가 올라갈 때마다 미사용자가 매일 제품을 봄 → ④ **대기자 명단 개통**("신청하면 다음날 아침 첫 브리핑") — 당기는 수요, 신청 자체가 자발 채택 증거 → ⑤ 자판기 등 도메인 횡전개.

### 6.2 타 기관 — 지렛대: 자기 데이터로 본 첫 브리핑

① **체험 생성기 선공급**: CSV 한 장을 넣으면 그 기관 데이터로 샘플 브리핑이 즉석 생성 — 어댑터 서식(12항목)은 체험 뒤에 내밈 ② **AI 챔피언 동기 네트워크**: 발표 마지막에 "여러분 기관 데이터로 돌려보실 분은 연락 주세요" — 심사장이 확산 1차 접점, 동기 기관 1곳 시범 적용이면 타 기관 실증 완성 ③ 범정부 채널(우수사례 공모·공공 SW 공유, 전 구성 무료 스택) ④ 확산 문장 규격화: **"분석 시스템 도입이 아니라, 직원의 보고 노동을 없애는 것부터 시작합니다."**

### 6.3 국민 — 지렛대: 이미 쌓인 데이터의 환원

① **소상공인 경영 브리핑**: 상생 매장 개인 사업자에게 자기 매장 3줄 브리핑 — 데이터가 이미 회사 POS에 있어 **수집 없이 권한과 전달만 열면 되는 즉시 실행형 국민 편익** (채널: 주간 인쇄 리포트부터 → 문자/알림톡은 심의 후) ② 간접 편익 명시: 민원 브리핑=대기시간 단축, 예산 브리핑=세금의 계획적 집행 ③ (장기) 역사 이용객 안내("지금 붐비는 시간")로의 확장 여지.

## 7. 평가 기준 6항목 자가 점검

| 항목(배점) | 대응 | 자평 |
|---|---|---|
| ① 고객과 문제 25% | 특정 인물화(혼자 매장 돌리는 고연령 점포장), 고통의 장면 2개, 멘토 의견이 출발점 — 인터뷰 인용문 확보 계획 | 강 (인용문 확보 전까지는 중상) |
| ② 해법 적정성 15% | 단순 대안과 정직 비교, AI 최소 사용(템플릿 우선), 무인 운영 | 강 |
| ③ 실제 작동 15% | 라이브 데모 전 과정, 목업 정직 고지, 멱등 재적재 시연 | 강 |
| ④ 사용성 15% | 허들 0개, 전문용어 노출 0, 배울 것 없는 제품 | 강 |
| ⑤ 채택·위험 15% | 채택 엔진=보고 대행, 실패 원인 3 자가 지목 + 이탈 방어 | 강 |
| ⑥ 확산 15% | 사람 경로+기술 경로, 준비물 패키지 | 중상 (실증 전) |

## 8. 정직한 고민 지점 (리스크)

**먼저, 해소된 고민 하나**: "고연령 사용자가 AI 키를 넣거나, POS에서 로컬 LLM을 돌려야 하는 것 아닌가?" → **서버측 생성 원칙(신문 배달 구조)으로 해소.** 문장은 새벽에 서버가 만들어 저장하고 매장 기기는 표시만 하므로 현장에는 키·설치·AI 개념이 없습니다. MIN은 템플릿 치환이라 토큰 소비 0이며, 정식에서 LLM을 쓰더라도 매장당 하루 약 1천 토큰(300곳 기준 월 2만 원 안팎) — 비용이 아니라 심의·배치 시간이 결정 변수입니다.

1. 브리핑 도달 채널 — 폐쇄망 환경에서 "배달"을 어디로 하나 (목업은 화면 상시 게시, 정식은 채널 확인 필요)
2. 보고 대행의 조직 수용 — 받는 쪽(권역·본사)이 새 표준 양식을 승인해야 이중 업무가 안 됨
3. 파일럿 섭외 — 권한·경로 미확정
4. 5분 안에 데모+서사 완주 — 리허설로 검증 필요
5. 상호평가 특성 — 공감 연출(30초 침묵 체험, 인물 서사)의 수위

## 9. 멘토님께 여쭙고 싶은 것 (오늘의 본론)

1. **피벗 타당성**: "분석 플랫폼 → 브리핑+보고 대행" 전환이 멘토님이 보신 현장 문제의 정답 방향인지요? 놓친 관점이 있다면?
2. **브리핑 채널**: 점포장에게 실제로 '도달'하려면 어떤 채널이 현실적일까요? (매장 PC 화면 상시 게시 / POS 개점 화면 / 인쇄물 / 기타 사내 수단)
3. **수신자 선언 전략의 현실성**: 확산 지렛대를 점포장 설득이 아니라 "보고 수신자의 선언"(권역 담당이 '이 양식으로 받겠습니다' 공지 → 점포장 자동 유입)으로 뒤집었습니다. 이 역전이 조직 문화상 가능할지, 가능하다면 어느 권역·누구부터 접근해야 할까요?
4. **파일럿 섭외**: 점포 1~3곳 섭외의 현실적 경로와, 협조를 얻기 좋은 점포 유형에 대한 조언을 부탁드립니다.
5. **"오늘 준비 한 줄"의 소재**: 시간대 준비 외에, 점포장이 진짜 반가워할 한 줄의 소재가 현장에 더 있을까요? (예: 날씨, 행사, 열차 지연…)
6. **5분 발표**: 데모 2분 30초 + 서사 2분 30초 배분이 적절한지, 심사에서 가장 힘줘야 할 한 장면은 무엇일지요?
