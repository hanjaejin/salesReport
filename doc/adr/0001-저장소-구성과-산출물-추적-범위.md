# ADR-0001. 저장소 구성과 산출물 추적 범위

- 상태: 채택
- 일자: 2026-08-27
- 관련 마일스톤: M0
- 결정자: 사용자 확인(AskUserQuestion — "git init 후 마일스톤별 커밋")

## 배경

명세 4장은 프로젝트 루트를 `pos-briefing/`으로 그리고 `data/`를 "DB 파일·산출물 (git 제외)"로 적었다.
그러나 명세 15장(배포)은 **`data/pos_mockup.db`를 저장소에 동봉**해 Streamlit Community Cloud에서
파이프라인 재실행 없이 읽기 전용으로 구동하라고 요구한다. 두 서술이 같은 경로를 두고 엇갈린다.

또한 실제 작업 디렉토리는 `C:\aistudy\workspace\project02_salesReport`이며, 여기에는 이미
`doc/`(명세·흐름도)와 `data/`(실샘플 엑셀 14종·쿼리 10종)가 놓여 있다.

## 결정

1. **프로젝트 루트는 현재 디렉토리(`project02_salesReport/`)를 그대로 쓴다.** `pos-briefing/`
   하위 디렉토리를 새로 만들지 않는다. 명세 4장 트리의 `pos-briefing/`은 프로젝트 이름을 가리키는
   자리표시자로 해석하고, 그 **아래 구조(`src/…`, `tests/`, `data/`)는 한 글자도 바꾸지 않는다.**
2. **`data/pos_mockup.db`는 평소 추적하지 않는다.** 개발 중 매 커밋마다 바이너리 전체가
   갈아치워지는 것을 피하기 위해서다. 배포 시점에 `git add -f data/pos_mockup.db`로 한 번 올린다.
3. **씨앗 엑셀(`data/*.xlsx`)과 쿼리(`data/*.txt`)는 추적하지 않는다.** 대신 ADR-0002에 따라
   여기서 추출한 상품 사전 JSON을 `src/generate/` 아래에 커밋해 배포 환경에서도 생성이 재현되게 한다.
4. 커밋 단위는 `doc/CLAUDE.md`의 사내 규칙을 따른다 — 마일스톤별 한국어 커밋 메시지
   `[M2] 합성 데이터 생성기: 점포별 시간대 프로파일 구현`, 구조 변경은 `[tidy]` 접두, Tidy First 분리.

## 근거

- **명세 4장 vs 15장 충돌 해소**: 15장이 배포라는 구체적 목적을 가진 더 늦은 서술이므로 DB 동봉이
  최종 요구다. 다만 "동봉"은 배포 시점의 상태를 말할 뿐 개발 중 매 커밋 추적을 요구하지 않는다.
  `-f` 강제 추가 한 번으로 두 요구를 모두 만족한다.
- **씨앗 엑셀 제외**: `DATA_TB_SBL202.xlsx` 하나가 9.2MB이고 data/ 전체가 약 10MB다. 이 중 실제로
  씨앗 역할을 하는 것은 `DATA_영수증데이터.xlsx` 한 개뿐이며, 여기서 뽑을 정보(상품 사전)는
  수십 KB JSON으로 충분히 표현된다. 원본 대신 추출물을 커밋하면 저장소가 가볍고, 생성 결과가
  엑셀 파일의 존재 여부에 의존하지 않아 **클라우드 배포에서도 결정적으로 재현**된다.
- **루트 신설 안 함**: `doc/`·`data/`가 이미 현 위치에 있어 하위 디렉토리를 새로 파면 상대 경로가
  둘로 갈라진다. 명세가 동결하라고 한 것은 테이블·컬럼명(불변식 5)과 `src/` 이하 모듈 경로이지
  저장소 최상위 폴더 이름이 아니다.

## 결과

- 긍정: 저장소 수 MB 이내 유지. 배포 절차가 `git add -f` 한 줄로 명시적.
- 부정: 배포 전 DB 동봉을 **잊을 수 있다.** → README의 배포 절차에 해당 명령을 못 박고,
  M5 완료 시 데모 체크리스트에서 확인한다.
- 부정: 씨앗 엑셀이 저장소에 없어 다른 사람이 클론하면 상품 사전을 **재추출할 수 없다.**
  → 추출 스크립트와 그 산출 JSON을 함께 커밋하고, JSON 안에 원본 파일명·추출 조건을 메타로 남긴다.

## 명세와의 관계

- 명세 4장 "data/ (git 제외)"와 15장 "DB 동봉"의 충돌을 **15장 우선**으로 해소했다.
- 명세 4장의 `src/` 이하 모듈 경로는 변경 없이 그대로 구현한다.
