# ADR-0002. 상품 사전은 실샘플에서 추출해 JSON으로 동결한다

- 상태: 채택
- 일자: 2026-08-27
- 관련 마일스톤: M0(결정) / M2(구현)
- 결정자: 사용자 확인(AskUserQuestion — "실샘플 664종 기반")

## 배경

명세 6.4는 상품 사전을 이렇게 규정한다: **"기본 30종 내장 — 실샘플 엑셀 있으면 대체 로드"**.
즉 두 갈래를 모두 허용하고 어느 쪽을 쓸지는 열어 두었다.

실측 결과 `data/DATA_영수증데이터.xlsx`는 명세 1장의 서술("점포 1곳·1일·거래 30건 이내")보다
훨씬 풍부하다:

| 항목 | 실측값 |
|---|---|
| 상품 행수 | 3,412행 |
| 영수증 수 | 2,344건 (점포 202246, 2026-07-15) |
| 고유 상품 | 664종 |
| 영수증당 평균 상품행수 | **1.456** (명세 6.5의 목표 평균 ≈1.48과 거의 일치) |
| 실 대분류 | 11종 — 음료·과자/스낵류·냉장·Fresh Food·담배·잡화·식료·냉동·주류·기타·신문/잡지 |

## 결정

1. **상품 사전은 실샘플 664종에서 추출한다.** `PLU_CD`·`GOODS_NM`·`ITEM_HEAD`·`ITEM_HEAD_NM`·
   대표가(`SALEPRICE` 중앙값)를 실제 값 그대로 쓴다.
2. **추출 결과를 `src/generate/seed_catalog.json`으로 동결해 커밋한다.** 합성 생성기는 이 JSON만
   읽는다. 엑셀은 런타임 의존이 아니라 **일회성 원천**이다(ADR-0001 3항).
3. **추출 스크립트 `src/generate/build_catalog.py`를 함께 커밋한다.** 씨앗 엑셀이 갱신되면
   이 스크립트를 다시 돌려 JSON을 재생성한다. 스크립트는 파이프라인 실행 경로에 포함되지 않는다.
4. JSON 안에 **메타 블록**을 둔다 — 원본 파일명, 추출 일자, 원본 행수/영수증수, 추출 조건.
   화면의 "목업 데이터" 배지가 주장하는 정직성을 데이터 자체가 뒷받침하게 한다.
5. 명세 6.4의 **품목 선택 확률(간편식 30 / 음료 30 / 스낵 15 / 유제품 15 / 생활 10)과
   시간대 보정(07~09시 간편식+10%p·음료+5%p, 12~13시 간편식+10%p)은 유지한다.**
   실 대분류 11종을 이 5개 확률 그룹에 매핑해 확률 구조를 보존한다(매핑표는 아래).

### 실 대분류 → 명세 6.4 확률 그룹 매핑

| 명세 확률 그룹 | 기본 확률 | 매핑되는 실 `ITEM_HEAD_NM` | 근거 |
|---|---|---|---|
| 간편식 | 30% | Fresh Food, 식료 | 삼각김밥·김밥·도시락류가 Fresh Food에 속한다 |
| 음료 | 30% | 음료 | 1:1 대응 |
| 스낵 | 15% | 과자/스낵류, 냉동 | 냉동은 얼음컵·아이스크림류로 스낵 성격 |
| 유제품 | 15% | 냉장 | 우유·요거트·치즈가 냉장 대분류에 속한다 |
| 생활 | 10% | 잡화, 신문/잡지, 기타 | 명세의 "생활" 정의(물티슈·마스크·우산류)에 대응 |
| **(제외)** | — | 담배, 주류 | 아래 "담배·주류 제외" 참조 |

### 담배·주류 제외

명세 6.4는 분류명을 **"주류담배 제외 생활"**로 적어 두 분류를 사전에서 빼는 것을 전제한다.
따라서 실샘플의 `담배`·`주류` 대분류는 사전에서 제외한다.

- 영향: 실샘플 매출의 담배 1,131,400원(전체의 약 15%)·주류 204,300원이 빠진다.
- 수용 이유: 브리핑은 "오늘 무엇을 진열할지"를 돕는 제품이고, 담배·주류는 진열 조언 대상이 아니다.
  또한 데모 화면에 담배 상품명이 TOP5로 노출되는 것은 발표 맥락에서 부적절하다.
- 이 제외는 **합성 데이터의 매출 구성이 실제 편의점과 다르다**는 뜻이다. 정식 단계에서 실데이터를
  연동하면 자동으로 해소된다(사전이 아니라 원천이 바뀌므로).

### 사전 규모

664종 전량이 아니라 **판매빈도 상위 120종**을 담는다. 5개 확률 그룹 각각이 최소 10종을 갖도록
그룹별로 상위 절단한다.

- 120종 근거: 명세 6.4의 30종은 "1일 30건"이라는 잘못된 전제에서 나온 수치다. 실제 씨앗은
  1일 2,344건이라 30종으로는 TOP5가 매일 같아져 브리핑이 단조로워진다. 반대로 664종 전량을 쓰면
  꼬리 상품이 대부분 하루 0~1건이라 상품 마트가 의미 없이 비대해진다.
- 그룹별 하한 10종: 특정 시간대 보정이 걸렸을 때 뽑을 후보가 고갈되지 않게 한다.

## 근거

- **씨앗의 목적**: 명세 1장이 실샘플의 역할을 "데이터가 아니라 **씨앗** — 실컬럼 구조·상품/가격
  사전·영수증당 1.4줄 패턴의 근거"라고 못 박았다. 상품 사전에 실값을 쓰는 것은 이 목적의 직접 실현이다.
- **데모 설득력**: TOP5에 `농심)백산수500ml 392건 1,000원`이 뜨는 것과 `생수500 1,100원`이 뜨는 것은
  심사위원이 받는 인상이 다르다. 전자는 "실제 시스템을 봤다"는 감각을 준다.
- **PLU_CD 정합**: 명세 6.4는 "PLU_CD는 '88'로 시작하는 13자리"를 요구했는데, 실샘플의 PLU는
  대부분 실제 바코드(8801043022781 등)로 이미 이 형식을 만족한다. 만족하지 않는 소수
  (`10279649` 티머니충전, `1171359100600` 만나바나나 등 비표준 길이)는 사전에서 제외해
  명세의 형식 요구를 그대로 지킨다.

## 결과

- 긍정: 화면·보고서의 상품명이 실제 편의점 상품이라 데모 설득력이 크다.
- 긍정: 가격이 실측값이라 영수증 금액 분포가 자연스럽고, 1인당 구매액이 현실적 범위로 나온다.
- 부정: 실제 점포 202246의 상품 구성이 가상 점포 3곳에 그대로 복제된다 — 세 점포의 상품 구성이
  등급별로 달라지지 않는다. **명세가 요구한 점포별 차등은 시간대 프로파일(6.3)이지 상품 구성이 아니므로
  범위를 넘지 않는다.** 상품 차등은 구현하지 않고, 개선 아이디어로만 남긴다(명세 14장 "명세에 없는 기능 추가 금지").
- 부정: 담배·주류 제외로 매출 구성이 실제와 다르다(위 "담배·주류 제외" 참조).
- 부정: 씨앗 엑셀 없이 클론하면 `build_catalog.py`를 돌릴 수 없다 → 산출 JSON을 커밋해 해소(결정 2항).

## 명세와의 관계

- 명세 6.4가 허용한 두 갈래 중 "실샘플 엑셀 대체 로드" 쪽을 선택했다. **명세 위반이 아니다.**
- 명세 6.4의 확률·시간대 보정 수치는 **변경하지 않고** 분류 매핑만 추가했다.
- 명세 6.4의 "PLU_CD는 '88'로 시작하는 13자리" 형식 요구는 사전 필터로 그대로 지킨다.
- 명세 6.4의 "기본 30종" 개수는 씨앗 실측(1일 2,344건)과 맞지 않아 120종으로 조정했다.
  **이것이 이 ADR에서 명세 수치를 벗어난 유일한 항목이다.**
