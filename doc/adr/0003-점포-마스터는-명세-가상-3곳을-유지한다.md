# ADR-0003. 점포 마스터는 명세 6.1의 가상 3곳을 유지한다

- 상태: 채택
- 일자: 2026-08-27
- 관련 마일스톤: M0(결정) / M2(구현)
- 결정자: 사용자 확인(AskUserQuestion — "명세 6.1 그대로")

## 배경

명세 6.1은 가상 점포 3곳(`901001` 중앙역 대형점 / `901002` 동부역 중형점 / `901003` 간이역 소형점)을
확정했다. 한편 씨앗 엑셀의 실제 점포는 `202246` 용산국철맞이방직영편의점이다.
상품 사전에 실값을 쓰기로 한 이상(ADR-0002), 점포도 실값으로 맞출지가 열린 질문이 된다.

## 결정

**명세 6.1의 가상 3곳을 그대로 쓴다.** 일평균 거래(800/300/80건)·변동폭(±15%/±15%/±20%)·
POS 대수(3/2/1)·등급(L/M/S)도 명세 표 그대로다. 실 점포코드 `202246`은 어디에도 등장시키지 않는다.

## 근거

- **정직성**: 화면 배지가 "🧪 목업 데이터"라고 고지하는데 점포명은 실제 점포라면 고지가 반쪽이 된다.
  실재하는 용산 점포에 13개월치 가상 매출을 붙이는 것은 오해의 소지가 있다 — 심사위원이
  "이게 용산점 실적인가?"라고 물을 여지를 아예 만들지 않는다.
- **명세 정합**: 6.3의 시간대 프로파일 표가 L/M/S 등급별로 정의돼 있고, 12장 데모 체크리스트가
  "L=아침 G2, M=점심 G2, S=G2 미발동·침묵일 존재"를 명시적으로 요구한다. 점포 구성이 명세와
  1:1이어야 이 체크리스트를 그대로 검증할 수 있다.
- **상품 사전과의 비대칭이 문제되지 않는 이유**: 상품명은 "어떤 물건이 팔리는가"라는 **사실의 어휘**여서
  실값이 이해를 돕는다. 반면 점포명은 "누구의 실적인가"라는 **귀속의 표지**여서 실값이 오해를 만든다.
  둘을 다르게 다루는 것이 일관성 없음이 아니라, 정직성 기준을 일관되게 적용한 결과다.

## 결과

- 긍정: 명세 12장 체크리스트를 수정 없이 그대로 실행할 수 있다.
- 긍정: 데모 중 "실제 점포 데이터인가?"라는 질문이 원천적으로 발생하지 않는다.
- 부정: 점포코드가 `901xxx`로 실 기간계 코드 체계(`2xxxxx`)와 다르다. Oracle 연동 시 점포 마스터는
  교체 대상이다. → 컬럼명·자료형은 동일하므로 값만 바뀌며, Extractor 교체 범위 안에 든다.

## 명세와의 관계

명세 6.1을 수정 없이 그대로 구현한다. 이 ADR은 **명세를 따르기로 한 결정 자체**의 근거 기록이다.
