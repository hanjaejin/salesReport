# ADR (Architecture Decision Record) — 30초 매장 브리핑 데모

이 디렉토리는 **명세에 없어서 구현 중 새로 내려야 했던 결정**만 기록한다.

## 원칙

- 명세(`doc/30초매장브리핑_바이브코딩_구현설계서_v1.3.1.md`와 그 부록)에 이미 확정된 값은
  ADR 대상이 아니다. 명세가 유일한 원천이며, ADR은 명세의 **빈칸을 메운 기록**이다.
- 명세를 **확장**하는 결정은 먼저 명세 부록에 반영하고, ADR에는 그 확장을 택한 근거를 남긴다
  (예: [ADR-0012](0012-결품-예상-카드를-명세-부록으로-확장한다.md) ↔ 부록 A).
- 명세와 충돌하는 결정은 ADR로 남길 수 없다. 충돌이 발견되면 명세를 따르고,
  충돌 사실 자체를 ADR의 "명세와의 관계" 절에 기록한다.
- 한 파일에 하나의 결정. 번호는 증가만 하고 재사용하지 않는다.
- 상태: `제안` → `채택` → (`폐기` | `대체됨(→ ADR-XXXX)`)

## 형식

MADR(Markdown Any Decision Record) 축약형 — 배경 / 결정 / 근거 / 결과 / 명세와의 관계.
