# ADR-0005. 파생 시드는 내장 `hash()` 대신 blake2b 안정 해시를 쓴다

- 상태: 채택
- 일자: 2026-08-27
- 관련 마일스톤: M1(구현) / M2·M4(사용)

## 배경

명세 3장과 `doc/CLAUDE.md` 불변식 4는 파생 시드 규칙을 이렇게 적었다.

> `seed = hash((20260723, DEPT_CD, SALEDATE))`

그리고 그 목적을 명시한다: **"어떤 부분 구간을 재생성해도 동일 데이터가 나온다 (멱등의 전제조건)"**.
명세 6.5도 같은 요구를 반복한다 — *"부분 구간 재생성 시에도 동일 결과가 나와야 `test_load_idempotent`가 성립한다."*

그러나 파이썬 내장 `hash()`는 **문자열에 대해 프로세스마다 다른 값**을 돌려준다
(PEP 456, 해시 랜덤화 — 해시충돌 DoS 방어 목적). `DEPT_CD`·`SALEDATE`가 문자열이므로
튜플 해시도 프로세스마다 달라진다. 실측:

```text
$ python -c 'print(hash((20260723, "901001", "20260722")))'   # 3회 반복
-1256842503901342595
-8236097194726309925
-5136424933355049285
```

명세 표기를 문자 그대로 구현하면 **파이프라인을 다시 돌릴 때마다 데이터가 바뀐다.**
`test_load_idempotent`(같은 기간 2회 적재 → 결과 동일)와 `test_partial_regen_deterministic`
(7월만 재생성 = 전체 생성 중 7월)이 같은 프로세스 안에서만 우연히 통과하고,
CLI를 두 번 실행하는 실제 사용에서는 깨진다. 명세 12장 데모 체크리스트의
`--from 20260701 --to 20260722` 재실행 시연도 성립하지 않는다.

## 결정

`src/common/config.derive_seed(dept_cd, saledate)`를 **blake2b 안정 해시**로 구현한다.

```python
payload = f"{BASE_SEED}|{dept_cd}|{saledate}".encode("utf-8")
digest = hashlib.blake2b(payload, digest_size=8).digest()
return int.from_bytes(digest, "big", signed=False) >> 1
```

- 입력 3요소(기본 시드 20260723, 점포, 날짜)와 그 결합 순서는 **명세 그대로**다.
- `>> 1`로 부호 비트를 떨어뜨려 `numpy.random.default_rng`가 요구하는 비음수 정수로 만든다.
- 난수 생성기는 `derive_rng()`가 `numpy.random.default_rng(derive_seed(...))`로 매번 새로 만든다
  — 명세 6.5의 "독립 Generator, 전역 순차 난수 금지"를 그대로 지킨다.

## 근거

- **명세의 의도를 지키는 유일한 방법**이다. `hash()`라는 표기는 "(시드, 점포, 날짜)를 섞어
  고유 시드를 얻는다"는 뜻으로 쓰인 것이지, CPython 내장 함수의 특정 구현을 지정한 것이 아니다.
  표기를 따르면 명시된 목적(부분 재생성 결정성)이 깨지므로, **목적이 표기를 이긴다.**
- 대안이었던 `PYTHONHASHSEED=0` 환경변수 고정은 기각했다. 실행 환경(로컬 CLI, pytest,
  Streamlit Cloud)마다 이 변수를 빠짐없이 심어야 하고, 하나라도 새면 조용히 틀린 데이터가 나온다.
  결정성을 **환경 설정이 아니라 코드**로 보장해야 한다.
- blake2b 선택 이유: 표준 라이브러리(`hashlib`)에 있어 의존성이 늘지 않고,
  `digest_size`를 지정할 수 있어 8바이트 정수로 바로 줄일 수 있다. 암호학적 강도는 필요 없지만
  균등 분포는 필요한데, 이 용도에 충분하다.

## 결과

- 긍정: 프로세스·머신·OS를 바꿔도 같은 (점포, 날짜)는 같은 데이터를 만든다. 실측으로
  별도 프로세스 3회 실행 시 시드·난수열이 모두 동일함을 확인했다.
- 긍정: `test_partial_regen_deterministic`을 **프로세스를 갈라서도** 검증할 수 있다.
- 부정: 명세 문구와 구현이 글자 단위로 다르다. → 이 ADR과 `derive_seed` docstring에
  근거를 남겨 다음 사람이 "명세대로 `hash()`로 되돌리는" 실수를 하지 않게 한다.
- 부정: 시드 값 자체는 명세를 문자대로 구현했을 때와 다르다. 명세가 특정 시드 **값**을
  고정한 적은 없으므로(고정한 것은 규칙과 재현성) 영향 없다.

## 명세와의 관계

명세 3장 파생 시드 규칙의 **표기**에서 벗어나고 **목적**을 지킨다.
불변식 4가 요구하는 "부분 재생성 결정성"은 이 결정으로만 실제로 달성된다.
