# ADR-0010. 정적 스냅샷은 자체완결 HTML로 만들고 저장소에 넣는다

- 상태: 채택
- 일자: 2026-08-27
- 관련 마일스톤: W1 (명세 15장 보험 2)

## 배경

명세 15장은 발표 3중 백업의 보험 2를 이렇게 규정했다.

> 녹화 영상(2분 30초) + **정적 HTML 스냅샷 3~4장**(브리핑·자세히·보고서·관리자 화면
> 저장본 — **서버·인터넷 없이 브라우저로 열림**) — USB + 클라우드 이중 보관.
> 발표장 인터넷 전면 장애 시 "녹화 시연 + 스냅샷 설명"으로 완주

"어떻게 만드는가"는 정하지 않았다. 브라우저 저장(Ctrl+S), 헤드리스 캡처, 직접 생성 셋 중
어느 쪽도 가능하다. 실제로 만들어 보니 정해야 할 것이 넷 있었다.

## 결정 1. 브라우저 저장이 아니라 코드로 생성한다

`src/report/snapshot.py` 가 DB를 읽어 HTML을 직접 만든다.
Streamlit 화면을 브라우저에서 "다른 이름으로 저장"하지 않는다.

**근거**

- **브라우저 저장본은 자체완결이 아니다.** Streamlit 페이지는 React 번들·웹소켓·
  폰트를 끌어오고, 저장하면 `_files` 폴더가 딸려 나오며 그중 일부는 서버 없이 동작하지 않는다.
  명세가 요구한 "서버·인터넷 없이 열림"을 만족시킬 수 없다.
- **재현되지 않는다.** 저장 시점의 화면 상태(스크롤·펼침·창 크기)에 따라 결과가 달라져
  누가 언제 저장했는지가 산출물에 새어 든다.
- 코드로 만들면 **같은 DB·같은 기준일이면 같은 파일**이 나온다. 테스트로 고정했다
  (관리자 장의 실측 소요 시간만 예외 — 측정값이므로).

이 결정의 실제 계기이기도 하다: 검증 과정에서 브라우저 캡처가 확대 배율 문제로
잘려 나갔다. **화면 캡처에 의존하는 백업은 캡처 환경에 의존한다.**

## 결정 2. 외부 참조를 하나도 두지 않는다

CDN·그림 파일·웹폰트를 전부 배제한다. CSS는 인라인 `<style>`,
차트는 **인라인 SVG로 직접 그린다**(`bar_chart_svg`·`line_chart_svg`).
글꼴은 시스템 글꼴 스택만 쓴다.

**근거**

명세 14장이 이미 "외부 CDN·API 호출 추가 금지(폐쇄망 대비)"를 규정했고,
스냅샷은 그 규율이 **가장 절실한** 산출물이다. 인터넷이 끊긴 상황을 위해 만드는 파일이
인터넷을 필요로 하면 존재 이유가 사라진다.

테스트가 이를 기계적으로 막는다 — 절대 URL·외부 스크립트·외부 스타일시트·
`@import`·`@font-face` 를 전부 금지하고, 링크는 같은 폴더의 스냅샷끼리만 허용한다.
따라서 폴더째 USB에 담아 더블클릭하면 열린다.

산출물은 5장 **31KB**다 (목차 + 4장).

## 결정 3. 관리자 스냅샷은 실제로 재생성을 돌려 전/후를 측정한다

`build_snapshots()` 는 기본적으로 최근 7일에 대해 `load_period()` 를 **실제로 호출**하고,
그 전후의 총매출·거래건수와 소요 시간을 기록한다.

**근거**

- 관리자 장의 내용은 "멱등이 실제로 성립했다"는 **증거**여야 한다. 같은 값을 두 칸에
  베껴 넣으면 증거가 아니라 주장이다.
- `load_period()` 는 멱등이므로 데이터는 바뀌지 않는다. 부작용이 없다.
- 다만 예상 못 한 실행을 막기 위해 `--no-regen` 을 두어 끌 수 있게 했고,
  전/후가 다르면 스냅샷에 "값이 달라졌어요"를 그대로 적는다 — **틀린 결과도 정직하게 남긴다.**

## 결정 4. 생성물을 `data/snapshot/` 에 두고 저장소에 커밋한다

`.gitignore` 로 막지 않는다. 일반적으로 생성물은 저장소에 넣지 않지만 여기서는 넣는다.

**근거**

명세 15장이 스냅샷을 **"USB + 클라우드 이중 보관"** 하라고 했고, 이 프로젝트에서
클라우드 보관처는 GitHub 저장소다. 커밋하지 않으면 이중 보관의 한쪽이 비어
백업 구성이 성립하지 않는다.

크기가 31KB로 작고, 결정적으로 재생성되므로 diff가 무의미하게 커지지 않는다.

## 결과

- 긍정: 인터넷·서버 0 의존. 폴더째 USB에 담아 어느 노트북에서든 열린다.
- 긍정: 데모의 완료 정의가 요구한 "세 점포의 브리핑이 서로 다름을 캡처로 증빙"이
  스크린샷이 아니라 **재현 가능한 산출물**로 남는다 — 브리핑 장 한 장에 세 점포가 들어 있다.
- 긍정: 브라우저 확대 배율·창 크기·테마 같은 캡처 환경 변수가 사라진다.
- 부정: 화면과 스냅샷이 **다른 코드**로 그려져 레이아웃이 완전히 같지는 않다.
  값은 같은 원천에서 오므로(브리핑 JSON·마트) **숫자는 어긋날 수 없고**, 테스트가 이를 지킨다.
- 부정: 화면에 새 요소가 생기면 스냅샷에도 손대야 한다. 데모 범위가 고정돼 있어 감당 가능하다.
- 부정: 스냅샷은 만든 시점의 DB를 반영한다. 데이터를 다시 구축하면 다시 만들어야 한다.
  → README의 배포 절차에 스냅샷 생성 단계를 넣었다.

## 명세와의 관계

명세 15장 보험 2를 구현한 것이다. "3~4장"을 4장 + 목차로,
"브리핑·자세히·보고서·관리자"를 그대로 각 한 장씩 만들었다.
명세 14장의 외부 호출 금지를 스냅샷에도 그대로 적용했다.
