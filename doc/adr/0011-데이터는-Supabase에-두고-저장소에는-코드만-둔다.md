# ADR-0011. 데이터는 Supabase에 두고 저장소에는 코드만 둔다

- 상태: 채택 (ADR-0009 결정 1을 **대체함**)
- 일자: 2026-08-27
- 관련 마일스톤: W1 (명세 15장 배포)
- 결정자: 사용자 지시

## 배경

ADR-0009는 전체 구축본이 171MB로 GitHub의 파일당 100MB 한도를 넘는 문제를,
원장(FACT 3종)을 비워 17.9MB로 줄인 뒤 `git add -f` 로 동봉하는 방식으로 풀었다.

그러나 그 방식은 **생성된 바이너리를 저장소 히스토리에 영구히 남긴다.**
데이터가 바뀔 때마다 18MB가 또 쌓이고, 나중에 빼려면 히스토리 재작성이 필요하다.

명세 3장은 저장소를 정하면서 이미 다음 단계를 적어 두었다.

> SQLite (`data/pos_mockup.db`) — SQLAlchemy Core 사용, **방언 종속 SQL 금지
> (추후 PostgreSQL/Supabase 교체 대비)**

그 규율을 지켜 온 값을 실측으로 확인했다. 전 소스에서 SQLite 종속은 **단 2곳**이었다.

| 위치 | 내용 |
|---|---|
| `config.get_engine` | `sqlite:///` URL 문자열 |
| `pipeline.slim_for_deploy` | `VACUUM` (SQLite 고유 의미) |

DDL(`Text`/`Integer`/`Float`)과 집계 SQL(`case`·`substr`·`coalesce`·`between`)은
전부 표준이라 손댈 곳이 없었다.

## 결정

**읽기 모델을 Supabase(PostgreSQL 17, `aichampion` 프로젝트, 서울 리전)에 두고,
저장소에는 코드·스키마·씨앗 사전만 둔다.** `data/pos_mockup.db` 는 계속 `.gitignore` 대상이다.

### 1. 연결 대상을 URL로 주입한다

`config.resolve_database_url()` 이 **인자 → 환경변수 `POS_BRIEFING_DB_URL` → 로컬 SQLite**
순으로 대상을 정한다. 코드는 어느 DB인지 모른 채 동작한다.

화면은 `app.main.database_url()` 로 **Streamlit secrets → 환경변수 → 로컬**을 살핀다.
클라우드 배포에서는 secrets에 연결 문자열을 넣고, 로컬 개발에서는 아무것도 설정하지 않는다.

### 2. 원격 연결에 `pool_pre_ping` 을 켠다

유휴 연결이 끊긴 뒤 첫 질의가 실패하는 것을 막는다(`pool_recycle=300` 병행).
Supabase 무료 티어는 연결을 오래 붙잡아 두지 않으므로, 이 설정이 없으면
**발표 도중 화면이 한 번 비었다가 새로고침해야 하는** 사고가 난다.

### 3. `src/load/publish.py` 가 읽기 모델만 옮긴다

| 옮기는 것 | 행수 | 옮기지 않는 것 |
|---|---|---|
| `DIM_STORE` | 3 | `FACT_RECEIPT` (463,544) |
| `MART_DAY_STORE` | 1,188 | `FACT_RECEIPT_ITEM` (685,917) |
| `MART_HOUR_STORE` | 21,417 | `FACT_PAYMENT` (486,840) |
| `MART_DAY_STORE_ITEM` | 108,993 | |
| `BRIEFING_DAILY` | 1,188 | |
| **합계** | **132,789행** | |

대상에 스키마가 없으면 만든다 — 사전 준비 없이 명령 한 줄로 끝난다.
원장 테이블도 **생성만** 하고 비워 둔다. 화면의 관리자 재생성 버튼이 그 자리를 채울 수 있어야 하기 때문이다.

배치(기본 2,000행)로 나눠 보내고, 원본을 청크로 읽어 전량을 메모리에 올리지 않는다.

### 4. 자격 증명은 코드·로그·화면 어디에도 남기지 않는다

- 대상 URL은 `POS_BRIEFING_TARGET_URL` 환경변수로 주는 것을 권한다 (셸 이력에 남지 않게).
- 로그에는 `mask_url()` 을 거쳐 `postgresql://***@host:5432/postgres` 형태로만 남는다.
- 화면 하단은 파일명 대신 "클라우드 데이터베이스"라고만 적는다.
- 사용자에게 키를 요구하지 않는 원칙(불변식 7)은 그대로다 — 값은 **운영자가 배포 설정에 넣고**,
  점포장은 URL만 연다.

### 5. `VACUUM` 은 SQLite에서만 실행한다

`config.is_sqlite()` 로 분기한다. PostgreSQL은 autovacuum이 처리하며 권한도 다르다.
이것이 코드에 남은 **유일한 방언 분기**다.

## 명세 14장과의 관계 — 정직하게 짚을 점

명세 14장은 "외부 CDN·API 호출 추가 금지**(폐쇄망 대비)**"를 규정했다.
원격 DB 연결은 이 금지의 대상이 아니라고 본다.

- 금지의 취지는 **화면이 제3자 서비스에 붙거나 모델을 내려받는 것**을 막는 데 있다.
  흐름도 FLOW 03·06이 "화면은 DB 읽기만"이라고 그린 그 DB가 어디 있는지는 규정하지 않았다.
- **폐쇄망 대비라는 취지도 유지된다.** 정식 단계에서는 연결 문자열이 망 안의 PostgreSQL을
  가리키면 된다. 오히려 SQLite 파일 동봉보다 폐쇄망 운영에 가까운 구조다.

다만 **데모 당일에는 외부 네트워크 의존이 하나 늘어난다**는 사실은 그대로다. 아래 참조.

## 결과

- 긍정: 저장소에 바이너리가 들어가지 않는다. 코드·스키마·씨앗 사전(28KB)만 남는다.
- 긍정: 데이터 갱신에 커밋이 필요 없다. `publish` 한 번이면 된다.
- 긍정: 명세 3장이 예고한 PostgreSQL 전환을 **지금 끝냈다.** 정식 단계 전환 비용이 사라졌다.
- 긍정: 실측 발행 132,789행 / 1.2초 (로컬 간). 원격은 왕복이 붙지만 일회성이다.

- **부정 (가장 중요): 발표 당일 살아 있어야 할 곳이 1곳에서 2곳으로 늘었다.**
  명세 15장의 보험 1(Hugging Face Spaces)은 "다른 사업자의 인프라로 방어"가 목적인데,
  데이터가 Supabase 한 곳이면 **주력과 보험 1이 같은 단일 장애점을 공유**한다.
  → 완화: 보험 2(오프라인 정적 스냅샷, ADR-0010)가 이미 있어 최악의 경우에도 완주할 수 있다.
  발표일 운영 체크리스트에 **Supabase 워밍업**을 추가한다.

- **부정: 무료 티어는 미사용 시 프로젝트를 재운다.** 같은 계정의 다른 프로젝트
  (`jaejinFirst Project`)가 이미 `INACTIVE` 상태인 것이 실례다.
  → 완화: 전날·30분 전 워밍업 절차에 포함한다.

- **부정: SQL 연결이 3회 모두 실패했다.** 관리 API는 정상이었다.
  → 원인을 **측정으로 특정했다** (아래 결정 5). 대응으로 스키마 생성을 `publish` 가
  직접 하도록 만들어 외부 도구 없이 끝나게 했다. 연결 문자열은 반드시
  **Session pooler**(포트 5432)를 쓴다 — Transaction pooler(6543)는
  준비된 구문을 지원하지 않아 SQLAlchemy의 `executemany` 와 맞지 않는다.

- 부정: `psycopg2-binary` 의존성이 늘었다. 로컬 SQLite만 쓸 때는 없어도 되지만
  클라우드 배포에는 필수라 `requirements.txt` 에 넣었다.

## 결정 5. 연결 실패의 원인을 추측이 아니라 측정으로 확정한다

처음에는 "IPv6 전용이라 그럴 것"이라고 **추측**하고 `aws-0-ap-northeast-2` 를 적었다.
그 문자열로는 영영 붙지 않는다. 세 경로를 실제로 두드려 보고서야 원인이 갈라졌다.

| 경로 | 결과 | 뜻 |
|---|---|---|
| `db.<ref>.supabase.co:5432` (Direct) | **DNS 실패** (`Name or service not known`) | IPv6 전용 — IPv4 망에서는 이름조차 풀리지 않는다 |
| `aws-0-...pooler.supabase.com:5432` | TCP 5ms, `(ENOTFOUND) tenant/user ... not found` | 호스트는 살아 있으나 **이 프로젝트의 풀러가 아니다** |
| **`aws-1-...pooler.supabase.com:5432`** | `password authentication failed` | **호스트·사용자가 정답** — 비밀번호만 있으면 된다 |

가짜 비밀번호로 두드리면 자격 증명을 다루지 않고도 이 판별이 된다.
`tenant/user not found` 는 **호스트 오류**인데 문구가 사용자 이야기를 해서
"비밀번호가 틀렸나" 로 오해하기 쉽다 — 실제로 한 번 헛짚었다.

**대응**: 세 문구를 `publish.CONNECT_HINTS` 에 표로 담고, `preflight()` 가
복사를 시작하기 **전에** 연결을 확인해 고칠 방법을 한 줄로 알려 준다.
`CONNECT_TIMEOUT_SEC = 10` 을 걸어 무한 대기도 막았다 — 발표 직전에 매달리지 않는다.

**남는 주의**: 풀러 접두사(`aws-0`/`aws-1`)는 **프로젝트마다 다르다.**
README에 "직접 적지 말고 대시보드 [Connect] 문자열을 복사하라"로 적었다.

## 결정 6. 발행 테이블에 RLS를 켜 두고 정책은 두지 않는다

Supabase의 `public` 스키마는 PostgREST로 자동 노출된다. RLS가 꺼져 있으면
**anon 키를 가진 누구나** 마트·브리핑을 통째로 읽을 수 있다.

11개 테이블 전부에 `ENABLE ROW LEVEL SECURITY` 만 걸고 정책은 만들지 않았다.

- anon·authenticated → 정책이 없으니 **전부 차단**.
- 화면·발행은 `postgres` 롤로 **직접 접속**하고, 이 롤은 `rolbypassrls = true` 다
  (실측 확인). 그래서 **아무것도 막히지 않는다.**

가상 점포의 합성 데이터라 유출 피해 자체는 없지만, 불변식 6(개인정보 컬럼 미생성)이
"애초에 위험을 만들지 않는다"는 태도인 만큼 노출 경로도 같은 기준으로 닫았다.

**주의**: 이 프로젝트는 다른 작업(`documents`, `rag_*`, `edu_*`)과 Supabase 프로젝트를
공유한다. 테이블명이 명세 4장 그대로라 충돌하지 않지만, 남의 테이블은 건드리지 않는다.

## 대체 관계

**ADR-0009 결정 1(배포용 DB에서 FACT를 비워 저장소에 동봉)을 대체한다.**
`--deploy` 플래그와 `slim_for_deploy()` 는 남겨 둔다 — 오프라인 배포나
Supabase를 쓰지 않는 대안 경로에서 여전히 유효하고, 테스트도 유지한다.

ADR-0009 결정 2(폐기 예정 Streamlit API 교체)는 그대로 유효하다.
