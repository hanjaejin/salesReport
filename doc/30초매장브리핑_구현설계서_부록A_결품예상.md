## A.1 왜 넣는가

본 명세 7.4의 2줄은 **"오늘 준비"** 를 말하는 자리다. 현재 문장은
*"아침(07~09시)에 하루 매출의 30.4%가 나와요 — 그 전에 진열을 확인해 보세요"* 이다.

점포장이 아침에 실제로 해야 하는 판단은 **"오늘 무엇이 떨어질 것인가"** 이고,
그 답은 매출만으로는 나오지 않는다. 재고와 결합해야 나온다.

씨앗 데이터에 이미 그 재료가 있다.

| 원천 | 정체 | 실측 |
|---|---|---|
| `TB_SBL202` | 매장 발주 기초데이터 | 1일 × 999점포 × 2,621품목 = 34,360행 |
| `TB_SEL639` | 부서별일수불 | 1일 × 1점포 × 801품목 |

`TB_SBL202`에는 `RUNNING_STOCK_QTY`(운영재고)·`PROPER_STOCK_QTY`(적정재고)·
`IPGO_QTY`(입고예정)·`SALE_AVERAGE_QTY`(매출평균)·`LEAD_TM`(리드타임)이 모두 있다.
실측에서 **운영재고 < 적정재고인 행이 30.6%(10,529건)** 로 결품 신호가 실제로 존재한다.

**중요**: 기간계가 이미 적정재고와 권고발주수량을 계산해 준다.
이 제품이 새로 만드는 것은 예측 모델이 아니라 **그 신호를 아침 3줄로 배달하는 것**이다
(흐름도 FLOW 01의 "시스템이 나른다").

## A.2 스키마 — `FACT_STOCK_SNAPSHOT` 추가

본 명세 4장 DDL에 아래 테이블 하나를 추가한다. **기존 10개 테이블은 그대로다.**

```sql
CREATE TABLE IF NOT EXISTS FACT_STOCK_SNAPSHOT (
  SALEDATE          TEXT NOT NULL,   -- 기준일자 YYYYMMDD
  DEPT_CD           TEXT NOT NULL,   -- 점포코드
  PLU_CD            TEXT NOT NULL,   -- 상품코드
  GOODS_NM          TEXT NOT NULL,   -- 상품명
  ITEM_HEAD_NM      TEXT NOT NULL,   -- 대분류명
  RUNNING_STOCK_QTY INTEGER NOT NULL, -- 운영재고수량
  IPGO_QTY          INTEGER NOT NULL, -- 입고예정수량
  SALE_AVERAGE_QTY  REAL    NOT NULL, -- 매출평균수량(1일)
  PROPER_STOCK_QTY  INTEGER NOT NULL, -- 적정재고수량
  ADVICE_ORDER_QTY  INTEGER NOT NULL, -- 권고발주수량 (표시 금지 — A.5 참조)
  LEAD_TM           INTEGER NOT NULL, -- 리드타임(일)
  PRIMARY KEY (SALEDATE, DEPT_CD, PLU_CD)
);
```

**컬럼명 근거 (불변식 5)**: 재고 관련 6개 컬럼은 `TB_SBL202`의 실컬럼명을 그대로 쓴다.
키 3개는 본 명세 4장이 이미 확정한 이름(`SALEDATE`·`DEPT_CD`·`PLU_CD`)을 따른다.

- `TB_SBL202`의 날짜 컬럼은 `ORDER_DATE`(발주일자)지만, 이 테이블은 **기준일의 재고 상태**를
  담으므로 본 명세의 `SALEDATE` 를 쓴다. 다른 FACT·MART와 같은 이름이라야 기간 조건이 통일된다.
- `TB_SBL202`의 상품 키는 `ITEM_CD`(7자리)지만, 본 명세 4장이 상품 식별자로 `PLU_CD`(바코드 13자리)를
  이미 확정했다(`FACT_RECEIPT_ITEM`·`MART_DAY_STORE_ITEM`). 두 체계를 섞으면 조인이 깨지므로
  `PLU_CD` 로 통일한다. `ITEM_CD ↔ PLU_CD` 매핑은 기간계 `TB_SMM001`(상품마스터)의
  `ITEM_CD ↔ BAR_CD` 로 해결되며, 이는 **Oracle 연동 시의 매핑 지점**으로 남긴다.

**grain**: 일 × 점포 × 상품. `MART_DAY_STORE_ITEM` 과 같은 단위라 조인해도 행이 증폭되지 않는다
(불변식 2 위배 없음).

## A.3 합성 생성 스펙 (본 명세 6장 확장)

재고는 **스냅샷**으로 만든다. 수불 흐름(기초→입고→판매→기말)은 모델링하지 않는다.

- 근거: 씨앗의 수불 검산(`기초+입고−판매−손실 = 재고`)이 801건 중 **544건(68%)만 일치**한다.
  나머지는 대입·대출·반품·조정 때문이며, 실제로 **재고가 음수인 품목이 40개** 있다.
  단순 공식으로 13개월을 만들면 화면에 음수 재고가 뜬다.
- 결품 판정에 필요한 것은 **기준일의 상태**이지 흐름의 이력이 아니다.

### 생성 규칙 (점포·날짜 파생 시드 — 불변식 4 유지)

상품 사전 120종 전체에 대해 매일 1행씩 만든다.

| 컬럼 | 규칙 |
|---|---|
| `SALE_AVERAGE_QTY` | `일평균거래 × 요일계수 × 그룹확률 × 그룹내가중치 × 평균수량` — 판매 생성과 **같은 파라미터**로 직접 계산해 통계적으로 정합시킨다. 소수 2자리 반올림 |
| `LEAD_TM` | 1 (85%) / 2 (15%) — 실측 평균 1.012 반영 |
| `PROPER_STOCK_QTY` | `ceil(SALE_AVERAGE_QTY × 재고보유일수)`, 재고보유일수 = 2. 최소 1 |
| `RUNNING_STOCK_QTY` | `round(PROPER_STOCK_QTY × 비율)`. **음수 불가** (하한 0). 비율은 아래 "재고 압박 모델" 참조 |
| `IPGO_QTY` | 20% 확률로 `ceil(SALE_AVERAGE_QTY × LEAD_TM)`, 나머지는 0 |
| `ADVICE_ORDER_QTY` | `max(0, PROPER_STOCK_QTY + LEAD_TM × SALE_AVERAGE_QTY − RUNNING_STOCK_QTY − IPGO_QTY)` 를 올림 |

난수는 전부 `derive_rng(dept_cd, saledate, "STOCK")` 에서 나온다. 판매 생성과 **다른 수열**을 쓴다 —
재고 규칙을 바꿔도 이미 구축·검증한 판매 데이터가 흔들리지 않게 하기 위해서다.
(`derive_seed` 는 용도가 비면 접미를 붙이지 않아 기존 판매 시드를 그대로 보존한다.)

### 재고 압박 모델 — 결품은 날 단위로 뭉친다

부족을 상품마다 독립된 확률로 뿌리면 **매일 누군가는 부족해진다.** 상품이 120종이므로
아주 낮은 확률에서도 최소 1개는 걸려 G3가 100% 발동하고, 그러면 **G2(시간대) 문장이 영영 나오지 않는다.**
명세 6.3이 프로파일을 차등한 이유("브리핑이 뻔해지는 실패")가 재고 쪽에서 재현되는 셈이다.

실제 결품은 배송 지연·주말 몰림처럼 **특정한 날에 뭉쳐서** 일어난다. 이를 모델에 반영한다.

```
압박도 = uniform(0, 1)                                   -- 그 날 그 점포에 하나
부족확률 = max(0, 압박도 − 0.45) × 0.12                   -- 45%의 날은 부족 0건

비율 = uniform(0.05, 0.45)  (부족한 상품)
     = uniform(1.05, 2.20)  (넉넉한 상품)
```

**넉넉한 상품의 하한 1.05는 의도적이다.** 소진일수 = 비율 × 재고보유일수(2) 이므로
1.05 × 2 = 2.1 > 리드타임 최대값 2일이 되어, 넉넉한 상품이 위험 목록에 새어 들어가지 않는다.

**실측 결과 (13개월 396일)**

| 점포 | G3 발동률 | 발동일 평균 위험 품목 | 최대 |
|---|---|---|---|
| 901001 (L) | 47.0% | 3.6개 | 9개 |
| 901002 (M) | 48.2% | 3.1개 | 9개 |
| 901003 (S) | 29.5% | 1.9개 | 5개 |

G3와 G2가 절반씩 2줄을 나눠 갖는다 — 두 신호가 모두 데모에서 보인다.

### 최종 카드 분포 (13개월 전체 구축 후 실측)

| 점포 | G4 구조 | G3 결품 | G2 시간대 | G6 침묵 |
|---|---|---|---|---|
| 901001 (L) | 82.6% | 47.0% | 52.5% | 0.0% |
| 901002 (M) | 81.1% | 48.2% | 36.4% | 1.8% |
| 901003 (S) | 84.6% | 29.5% | 39.6% | 3.5% |

**세 점포가 G3·G2·G6를 하나씩 보여 주는 날이 396일 중 72일**이다.
부록 A 이전의 데모 조건(L=아침 G2 / M=점심 G2 / S=침묵)이 14일이었던 것에 비해
훨씬 자주 성립하며, 2줄의 세 가지 상태를 한 화면 세트에서 모두 보여 줄 수 있다.

## A.4 결품 판정 규칙 (본 명세 7.3 확장)

### 위험 품목

한 상품이 아래 **두 조건을 모두** 만족하면 위험 품목이다.

```
소진일수 = (RUNNING_STOCK_QTY + IPGO_QTY) / SALE_AVERAGE_QTY     (0 나눗셈 방어)

① 소진일수 <= LEAD_TM        -- 지금 발주해도 도착 전에 떨어진다
② SALE_AVERAGE_QTY >= 1.0    -- 하루 1개도 안 나가는 꼬리 상품은 제외
```

②가 없으면 회전이 거의 없는 상품이 매일 위험 목록을 채워 신호가 무의미해진다.

### 카드

| ID | 발동 조건 | 우선순위 | 차지하는 줄 |
|---|---|---|---|
| G4 구조 | `abs(prev_diff_pct) >= 5.0` | 1 | 3줄 |
| **G3 결품** | **위험 품목 >= 1개** | **2** | **2줄** |
| G2 시간대 | `peak_block.share_pct >= 25.0` | 3 | 2줄 |
| G6 무제안 | 위 모두 미발동 | — | 2·3줄 |

**G3는 G2보다 우선한다.** 둘 다 "오늘 준비"(2줄)를 말하는데, 물건이 떨어지는 일이
진열 시점보다 급하기 때문이다. G3가 발동하면 G2는 카드 목록에 넣지 않는다.

카드는 여전히 **최대 2개**다 (G4 + G3/G2 중 하나). 없으면 G6 1개.
본 명세 7.3의 카드 개수 규칙은 바뀌지 않는다.

## A.5 문장 (본 명세 7.4 확장)

2줄 G3 발동형만 추가한다. **1줄·3줄과 기존 2줄 문자열은 하나도 바꾸지 않는다.**

로테이션 변형 2종을 두며, 선택은 본 명세 7.4대로 `(날짜, 점포)` 파생 시드로 결정한다.

### 변형 A

| 위험 품목 수 | 문자열 |
|---|---|
| 1개 | `{goods_nm} 재고가 얼마 남지 않았어요 — 오늘 채워 두는 게 좋아요` |
| 2개 이상 | `{goods_nm} 외 {other_count}개 상품의 재고가 얼마 남지 않았어요 — 오늘 채워 두는 게 좋아요` |

### 변형 B

| 위험 품목 수 | 문자열 |
|---|---|
| 1개 | `재고가 얼마 남지 않은 상품이 있어요 — {goods_nm}부터 확인해 보세요` |
| 2개 이상 | `재고가 얼마 남지 않은 상품이 {risk_count}개 있어요 — {goods_nm}부터 확인해 보세요` |

`{goods_nm}` 은 **가장 급한 1품목** — 소진일수가 가장 작은 상품. 동률이면 `SALE_AVERAGE_QTY` 가 큰 쪽.

### 지켜야 할 금지 (본 명세 7.4·14장 그대로 적용)

- **발주 수량을 제시하지 않는다.** `ADVICE_ORDER_QTY` 는 테이블에만 두고 문장·화면 어디에도 쓰지 않는다.
  본 명세 7.4가 "발주 수량 제시"를 명시적으로 금지했다.
- **원인을 단정하지 않는다.** "~때문에 떨어집니다" 금지. "얼마 남지 않았어요"·"확인해 보세요"만.
- **전문용어를 쓰지 않는다.** 결품·적정재고·리드타임·소진일수를 문장에 노출하지 않는다.
- **문장 계층은 산술을 하지 않는다** (불변식 1). `other_count`·`risk_count` 는 계산 JSON에 미리 담는다.
- 조사 문제를 피하려고 `{goods_nm} 재고가` / `{goods_nm}부터` 형태를 쓴다 — 받침 유무와 무관하게 자연스럽다.

## A.6 계산 JSON 확장 (본 명세 7.2 확장)

```json
"stock_risk": {
  "risk_count": 3,
  "other_count": 2,
  "top": {"goods_nm": "농심)백산수500ml", "stock_qty": 12, "sale_average_qty": 41.2, "days_left": 0.3},
  "items": [
    {"goods_nm": "...", "stock_qty": 12, "incoming_qty": 0, "sale_average_qty": 41.2, "days_left": 0.3}
  ]
}
```

- `items` 는 소진일수 오름차순, 최대 5개. 자세히 화면에서만 쓴다.
- `days_left` 는 소수 1자리로 저장 시점에 반올림 (본 명세 7.4 표기 규칙).
- 위험 품목이 없으면 `risk_count: 0`, `top: null`, `items: []`.

## A.7 화면 (본 명세 9장 확장)

- **브리핑 2줄**: G3 발동 시 A.5 문장을 표시한다. 구조는 그대로 3줄.
- **자세히 보기**: 기존 4개 항목 뒤에 `#### 곧 떨어질 수 있는 상품` 표를 추가한다.
  컬럼은 `상품 / 남은 재고 / 하루 평균 판매`. **권고발주수량은 넣지 않는다.**
  위험 품목이 없으면 "지금은 부족한 상품이 없어요"를 표시한다.
- **일일 보고서**: `재고` 시트를 추가한다 (같은 3개 컬럼).
- **정적 스냅샷**: 자세히 장에 같은 표를 반영한다.
